# Fix: Emotional notification shows inflated missed-day count

## Problem
User missed 1 day but received a notification saying they missed 3 days.

## Root Causes

### Primary: Stale `lastLogDate` in user document
When a user submits an amal log, the flow in `amal_provider.dart:400-521` is:
1. `saveAmalLog(log)` — saves the log doc (succeeds)
2. `updateStreak(uid, ..., lastLogDate: hijri)` — updates user doc (in try-catch, **can fail silently**)
3. `_trySyncSubmittedLog(log)` — background fallback (also catches errors silently)

If step 2 fails (Firestore error, network issue), the log is saved but `lastLogDate` remains stale. The user sees success, but the next notification uses the old `lastLogDate`, computing an inflated `daysMissed`.

### Secondary: No verification against actual logs
`scheduleSmartReminders()` relies solely on `lastLogDate` from the user document. It never cross-checks against actual `amal_logs` documents, even though `_hasLoggedIslamicDate()` already exists for exactly this purpose.

## Fix (2 parts)

### Part 1: Verify `daysMissed` against actual Firestore logs
**File**: `lib/core/services/notification_service.dart`

In `scheduleSmartReminders()` (line 333-337), after computing `daysMissed` from `lastLogDate`, add verification by walking backwards through recent dates checking actual `amal_logs` docs.

**Replace lines 333-337:**
```dart
// Calculate days missed
int daysMissed = 0;
if (lastLogDate.isNotEmpty && lastLogDate != today) {
  daysMissed = IslamicDateService.daysBetween(lastLogDate, today).abs();
}
```

**With:**
```dart
// Calculate days missed from lastLogDate
int daysMissed = 0;
if (lastLogDate.isNotEmpty && lastLogDate != today) {
  daysMissed = IslamicDateService.daysBetween(lastLogDate, today).abs();
}

// Verify against actual Firestore log entries to catch stale lastLogDate.
if (daysMissed > 0) {
  final verified = await _countVerifiedMissedDays(
    today: today,
    maxDays: daysMissed,
  );
  if (verified < daysMissed) daysMissed = verified;
}
```

**Add new helper method** after `_hasLoggedIslamicDate` (~line 657):
```dart
/// Walk backwards from yesterday, counting consecutive missing days
/// by checking actual Firestore log documents. Caps at [maxDays] reads.
Future<int> _countVerifiedMissedDays({
  required String today,
  required int maxDays,
}) async {
  if (maxDays <= 0) return 0;
  final checkLimit = maxDays.clamp(0, 7);
  int verifiedMissed = 0;
  String checkDate = today;
  for (var i = 0; i < checkLimit; i++) {
    checkDate = IslamicDateService.shiftStorageByDays(checkDate, -1);
    if (await _hasLoggedIslamicDate(checkDate)) break;
    verifiedMissed++;
  }
  return verifiedMissed >= checkLimit && maxDays > checkLimit
      ? maxDays
      : verifiedMissed;
}
```

### Part 2: Make `lastLogDate` update more resilient
**File**: `lib/providers/amal_provider.dart`

After `saveAmalLog()` succeeds (line 442), update `lastLogDate` immediately as a separate Firestore write, outside the streak try-catch. This ensures `lastLogDate` is fresh even if the full `updateStreak` call fails.

**After line 442** (`await fs.saveAmalLog(log, state.fields);`), add:
```dart
// Ensure lastLogDate is always updated when the log is saved,
// even if the full updateStreak call fails.
unawaited(fs.updateUserLastLogDate(user.uid, hijri).catchError((_) {}));
```

This uses the existing `updateUserLastLogDate()` method (firestore_service.dart:472-474) which is a lightweight single-field update.
