# Admin Update Modal — Implementation Plan

## Overview
Add an admin-controlled version update modal that compares the installed app version against a Firestore `app_config` document. When a newer version is available, a modal is shown with an update link to the Play Store. Admins can configure each release as **mandatory** (non-dismissible) or **soft** (dismissable, reappears on next launch).

## Firestore Schema

**Collection:** `app_config`  
**Document:** `current`

```json
{
  "latestVersion": "1.1.0",
  "latestVersionCode": 10,
  "playStoreUrl": "https://play.google.com/store/apps/details?id=com.amol.tracker",
  "updateTitle": "New Update Available",
  "updateMessage": "A new version of Amol Tracker is available. Please update for the best experience.",
  "forceUpdate": true,
  "minSupportedVersionCode": 9,
  "isActive": true,
  "updatedAt": "<server_timestamp>"
}
```

- `forceUpdate: true` → mandatory (back button disabled, can't dismiss)
- `forceUpdate: false` → soft (X button to dismiss, reappears next launch)
- `minSupportedVersionCode` → below this, app is blocked entirely (optional future use)

## Files to Create

### 1. `lib/models/app_config_model.dart`
- `AppConfigModel` with fields: `latestVersion`, `latestVersionCode`, `playStoreUrl`, `updateTitle`, `updateMessage`, `forceUpdate`, `minSupportedVersionCode`, `isActive`
- `AppConfigModel.fromDoc(DocumentSnapshot)` factory

### 2. `lib/providers/app_config_provider.dart`
- StreamProvider watching `app_config/current` document
- Derived provider that compares installed version (via `package_info_plus`) against Firestore config

### 3. `lib/shared/widgets/update_modal.dart`
- Dialog widget following `AnnouncementModal` patterns (emeraldDeep bg, gold accents)
- Shows: update icon, title, message, version info (current → latest), Play Store link button
- If `forceUpdate: true`: no close button, back button intercepted, only "Update" action
- If `forceUpdate: false`: close button (X), "Update" and "Later" buttons
- Uses `launchExternalUrl()` to open Play Store
- Static `show()` method for easy invocation

### 4. `lib/shared/widgets/update_check_wrapper.dart`
- Wrapper widget placed in app builder chain (like `BadgeCelebrationHost`)
- Listens to update status provider, shows `UpdateModal` when update available
- Handles back button interception for force updates via `PopScope`

## Files to Modify

## Implementation Order

2. Service methods in `firestore_service.dart`
3. Provider (`app_config_provider.dart`)
4. Modal widget (`update_modal.dart`)
5. Host wrapper (`update_check_wrapper.dart`)
6. Wire into `app.dart`
7. Admin screen (`admin_app_config_screen.dart`)
8. Routing (routes.dart + router.dart + admin_config.dart)
9. Entry point in more_screen.dart

## Verification

1. **Soft update**: Set `forceUpdate: false` and `latestVersionCode` higher than installed -> modal appears, can dismiss, reappears on resume
2. **Force update**: Set `forceUpdate: true` -> modal appears, no close button, back blocked
3. **No update**: Set `latestVersionCode` equal to or below installed -> no modal
4. **Admin form**: Navigate to admin screen, update values, verify Firestore write
5. **Non-admin**: Non-admin user should not see the admin config screen entry
