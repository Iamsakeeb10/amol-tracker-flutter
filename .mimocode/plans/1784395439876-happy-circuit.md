# Fix: Prayer selections lost after reinstall (wrong prayers shown in expand row)

## Problem

After uninstall + reinstall, the `FardPrayerExpandRow` shows wrong prayers as completed. For example, if user completed Dhuhr, Asr, Maghrib, Isha (indices `{1,2,3,4}`), the UI shows the first 4 prayers (Fajr, Dhuhr, Asr, Maghrib = indices `{0,1,2,3}`) instead.

**Root Cause**: Prayer selections are stored in two places:
1. Firestore `AmalLogModel.prayers` field (server-side, survives reinstall)
2. Hive local key `selections_${uid}_${hijri}` (client-side, wiped on reinstall)

On reinstall, the code reads from the Hive selections key (which is empty), and `resolvePrayerSelection()` falls back to a left-to-right fill based on the count. The Firestore `model.prayers` field **already has the correct data** but is **never used as a fallback**.

## Fix

Use `AmalLogModel.prayers` as a fallback when the Hive selections cache is missing. Three locations need changes:

### 1. `lib/providers/amal_provider.dart` — `_load()` Firestore path (lines 284-286)

**Current**: Only reads from Hive selections key.
**Fix**: If Hive selections are empty, fall back to `fromFs.prayers`.

```dart
// BEFORE:
final storedSelections = _parsePrayerSelections(
  LocalStorageService.getLog(_selectionsHiveKey(hijri)),
);

// AFTER:
var storedSelections = _parsePrayerSelections(
  LocalStorageService.getLog(_selectionsHiveKey(hijri)),
);
// Fallback: use prayer selections persisted in Firestore (survives reinstall)
if (storedSelections.isEmpty && fromFs.prayers.isNotEmpty) {
  storedSelections = fromFs.prayers.map((k, v) => MapEntry(k, v.toSet()));
}
```

### 2. `lib/providers/amal_provider.dart` — `_load()` Hive cache path (lines 319-321)

**Current**: Only reads from Hive selections key.
**Fix**: If Hive selections are empty, fall back to `model.prayers`.

```dart
// BEFORE:
final storedSelections = _parsePrayerSelections(
  LocalStorageService.getLog(_selectionsHiveKey(hijri)),
);

// AFTER:
var storedSelections = _parsePrayerSelections(
  LocalStorageService.getLog(_selectionsHiveKey(hijri)),
);
if (storedSelections.isEmpty && model.prayers.isNotEmpty) {
  storedSelections = model.prayers.map((k, v) => MapEntry(k, v.toSet()));
}
```

### 3. `lib/features/history/presentation/screens/edit_amal_screen.dart` — `initState()` (lines 62-77) and `ref.listen` callback (lines 253-267)

**Current**: Only reads from Hive selections key.
**Fix**: If Hive selections are empty, fall back to `widget.existingLog!.prayers`.

In `initState()`, after the existing Hive read block (around line 76):
```dart
// Fallback: use prayer selections from the Firestore model (survives reinstall)
if (_prayerSelections.isEmpty && widget.existingLog!.prayers.isNotEmpty) {
  for (final entry in widget.existingLog!.prayers.entries) {
    _prayerSelections[entry.key] = entry.value.toSet();
  }
}
```

Same pattern for the `ref.listen` callback block (around line 267).
