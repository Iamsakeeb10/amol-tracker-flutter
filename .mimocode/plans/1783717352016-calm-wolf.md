# Streak Bottom Sheet Implementation Plan

## Goal
Add a streak detail bottom sheet that opens when the user taps the streak pill in the home header. Shows the last 7 days date-wise with completed/missed/pending status, score, navigation to previous/next weeks, and reliable stats.

## Data Reliability Rules (user requirement: "only reliable values")

| Day status | How determined | Reliable? |
|---|---|---|
| Completed | `dayDetailLogProvider` returns a log with `score > 0` | Yes |
| Missed | Past day, no log exists, not today | Yes |
| Today (pending) | `hijriDate == today && !isSubmitted` | Yes |
| Today (done) | `hijriDate == today && isSubmitted` | Yes |
| Pre-account | Before `user.createdAt` | Yes |
| Future | After today | Yes (but not shown in the 7-day window) |
| Frozen | Cannot determine which specific day a freeze was applied to | **No — NOT shown** |

**What we show reliably:** currentStreak, bestStreak, freeze availability this week, per-day completed/missed/pending status, per-day score.

**What we deliberately omit:** Per-day freeze indicator (no reliable per-day data), per-day streak count (not stored), "streak that day" (already shows "not stored" in day_detail_screen.dart:168-169).

## Files to Create

### 1. `lib/features/home/presentation/widgets/streak_bottom_sheet.dart` (NEW)

The main bottom sheet widget. `ConsumerStatefulWidget` that:

**State:**
- `_weekOffset` (int, 0 = current week, negative = past weeks)
- `_selectedIndex` (int, 0-6, which day card is tapped)
- `_dayLogs` (Map<String, AmalLogModel?>, cached fetched logs)
- `_isLoading` (bool)
- `_accountCreatedHijri` (String, from user model)

**Data loading:**
- On init and when `_weekOffset` changes, compute 7 Hijri dates using `IslamicDateService.shiftStorageByDays(today, offset)` for offsets `[_weekOffset - 6, ..., _weekOffset]`
- Batch-fetch logs via `Future.wait` using `dayDetailLogProvider` for each date
- Cache results in `_dayLogs`

**Day status resolution logic:**
```
for each hijriDate in the 7-day window:
  if hijriDate < accountCreatedHijri → StreakDayStatus.preAccount
  if hijriDate > today → (shouldn't happen, we don't show future)
  if hijriDate == today:
    if isSubmitted → StreakDayStatus.completed (with score from submittedLog)
    else → StreakDayStatus.today (pending)
  else (past day):
    if log exists and score > 0 → StreakDayStatus.completed
    if log exists and score == 0 → StreakDayStatus.missed (opened but no amal)
    if no log → StreakDayStatus.missed
```

**Navigation limits:**
- Previous week: allowed if the earliest date in the target week >= account creation date
- Next week: allowed if `_weekOffset < 0` (never beyond today)
- When navigating, reset `_selectedIndex` to last non-future day

**Layout (top to bottom):**
1. Drag handle bar (36w x 4h, `AppColors.cardBorder`)
2. Header row: fire icon + "X day streak" text + close button
3. Stats row: Best streak pill + Freeze availability pill (only if freeze is available this week)
4. Section label: "Last 7 days" (localized)
5. Day cards: horizontal `ListView`, 7 cards, each ~58w
6. Week nav row: "< Previous" and "Next >" with disabled states
7. Day detail card: shows score, status text, and Hijri date for selected day
8. Bottom padding

**Static `show()` method:**
```dart
static Future<void> show(BuildContext context, {required String uid}) {
  return showModalBottomSheet<void>(
    context: context,
    isScrollControlled: true,
    backgroundColor: Colors.transparent,
    builder: (_) => StreakBottomSheet(uid: uid),
  );
}
```

### 2. Internal widgets (in same file, private)

**`_DayCard`** — Single day column card:
- Width: 58.w, border radius: 14.r
- Background/border color based on status:
  - completed: `AppColors.successLight` bg, `AppColors.success` border (at 30% alpha)
  - missed: `AppColors.dangerLight` bg, `AppColors.danger` border (at 30% alpha)
  - today: `AppColors.goldCard` bg, `AppColors.goldBorder` border
  - preAccount: `AppColors.cardDark` bg, `AppColors.cardBorder` border (dimmed)
- Content: weekday abbreviation, status icon (checkmark/x/hourglass/circle), Hijri day number, score or status label
- Selected state: gold border at 60% alpha, subtle gold shadow
- Uses `AppTextStyles.label` for weekday, `AppTextStyles.bodySmall` for Hijri day, `AppTextStyles.pill` for score/status

**`_DayDetailCard`** — Detail view for selected day:
- `CardContainer` with `AppColors.cardDark` bg
- Shows: Hijri date display, weekday, score (if completed), status text
- If `completed`: show score with `AppTextStyles.goldNumeric`
- If `missed`: show "No log submitted" message with warning icon
- If `today` pending: show "Not yet submitted" with hourglass icon
- If `preAccount`: show "Before account creation" muted text

**`_WeekNavRow`** — Previous/Next week buttons:
- Row with two `TextButton`s
- Previous: `Icons.chevron_left` + "Previous" text
- Next: "Next" text + `Icons.chevron_right`
- Disabled state: `AppColors.textMuted` color, `onTap: null`
- Enabled state: `AppColors.gold` color

## Edge Cases Handled

1. **New user with no logs**: All past days show "missed" status (reliable — they truly didn't log)
2. **Today not submitted**: Shows as "pending" with hourglass icon
3. **Today submitted**: Shows as "completed" with score
4. **Freeze used this week**: Stats row shows "Freeze used" pill (we know it was used, just not which day)
5. **Freeze available**: Stats row shows "Freeze available" pill
6. **Navigation to very old dates**: Limited by account creation date — Previous disabled when earliest visible date would be before account creation
7. **No forward navigation**: Next week disabled when `_weekOffset == 0` (current week is the latest)
8. **Loading state**: Show shimmer/progress while fetching logs
9. **Firestore errors**: Gracefully show "missed" for days where log fetch fails (we can't distinguish "no log" from "fetch error", but showing missed is safer than crashing)
10. **Hijri date edge cases**: All date math goes through `IslamicDateService.shiftStorageByDays()` which bridges through Gregorian — handles month/year boundaries correctly
