# Fix: Frozen day not showing with frozen styling in streak bottom sheet

## Problem

When a user freezes a missed day (yesterday), the streak bottom sheet's `_resolveDay()` method should return `StreakDayStatus.frozen` for that date, showing ice-blue background, snowflake icon, and "Frozen" label. Instead, it falls through to `StreakDayStatus.missed` (red X).

## Root Cause

The `_resolveDay()` method (line 199) reads the user model via `ref.read(currentUserProvider).value` (line 201), which is a **separate read** from the `build()` method's `ref.watch(currentUserProvider).value` (line 296). While both should return the same value within a single build cycle, passing the user directly is both cleaner and eliminates any potential stale-read issues.

More importantly, the frozen check at lines 270-281 is **correct on paper** — it checks `user.streakFreezeDate.isNotEmpty && hijriDate == user.streakFreezeDate`. The tracking via `streakFreezeDate` in the user model **is implemented** (set by `applyFreeze()` in `amal_provider.dart:496`).

The fix is straightforward: pass the already-resolved `user` from `build()` into `_resolveDay()` to ensure the same snapshot is used.

## Changes

### File: `lib/features/home/presentation/widgets/streak_bottom_sheet.dart`

**1. Add `UserModel? user` parameter to `_resolveDay` (line 199)**

```dart
// Before:
StreakDay _resolveDay(String hijriDate, String locale) {
    final today = _today;
    final user = ref.read(currentUserProvider).value;
    ...

// After:
StreakDay _resolveDay(String hijriDate, String locale, UserModel? user) {
    final today = _today;
    ...
```

Remove line 201 (`final user = ref.read(currentUserProvider).value;`).

**2. Update call site in `build()` (line 311)**

```dart
// Before:
final days = _visibleDates.map((d) => _resolveDay(d, locale)).toList();

// After:
final days = _visibleDates.map((d) => _resolveDay(d, locale, user)).toList();
```

This ensures `_resolveDay` uses the same `user` snapshot that `build()` obtained via `ref.watch`, eliminating any stale-read possibility.
