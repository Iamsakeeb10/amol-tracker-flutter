# Leaderboard: Pagination + Fixed User Card

## Files to modify
1. `lib/features/leaderboard/presentation/screens/leaderboard_screen.dart` — main changes
2. `lib/providers/leaderboard_provider.dart` — convert FutureProviders to AsyncNotifiers with `loadMore()`
3. `lib/core/services/firestore_service.dart` — add `startAfter` cursor support to `streakLeaderboard()`
4. `lib/core/services/quiz_leaderboard_service.dart` — add limit/cursor param to `fetchLeaderboard()`

---

## Architecture

### Pagination strategy per leaderboard type

| Type | Current | Strategy | Why |
|---|---|---|---|
| **Streak** | `.limit(50)`, no cursor | Add `startAfter` cursor, page size 20 | Already server-ordered; simple cursor on `currentStreak` field |
| **Daily** | Stream, truncate to 20 | Keep stream for real-time top 20; add client-side incremental render for overflow | Stream provides live updates; cursor on stream path is complex |
| **Weekly** | Fetch all, aggregate client-side | Client-side incremental render (page size 20) | Aggregation requires all raw docs; can't paginate server-side without pre-aggregation |
| **Monthly** | Fetch all, aggregate client-side | Client-side incremental render (page size 20) | Same as weekly |
| **Quiz** | Full collectionGroup scan | Client-side incremental render (page size 20) | Full scan required for ranking |

### Provider changes (`leaderboard_provider.dart`)

Convert each `FutureProvider<List<LeaderboardEntry>>` to `AsyncNotifier`-style with pagination state:

```dart
// New shared state wrapper
class LeaderboardState {
  final List<LeaderboardEntry> entries;
  final bool hasMore;
  final bool isLoadingMore;
  final int displayedCount;
  static const pageSize = 20;
  
  List<LeaderboardEntry> get displayed => entries.take(displayedCount).toList();
}
```

For **streak** (server-side pagination possible):
- Add `startAfter` param to `firestore_service.streakLeaderboard()`
- Notifier loads page 1 (20 items), `loadMore()` fetches next 20 via cursor
- `hasMore` = `fetchedCount == pageSize`

For **weekly/monthly/quiz/daily** (client-side pagination):
- Fetch all entries as before (single request)
- Notifier stores full list, exposes `displayedCount`
- `loadMore()` increments `displayedCount` by `pageSize` (20)
- `hasMore` = `displayedCount < entries.length`

#### 3. Filter user from normal list when pinned
When `userIndex >= 5`, skip the current user in `SliverList.builder`:
```dart
final visibleEntries = (userIndex >= 5)
    ? [for (int i = 0; i < entries.length; i++) if (i != userIndex) entries[i]]
    : entries;
```

#### 4. Pin threshold change
- Current: `userIndex >= 3` → show pinned card
- New: `userIndex >= 5` → show pinned card at bottom (outside scroll)
- User at rank 1–5 → appears normally in the list

#### 5. Pinned card — no margin, full width
- Wrapped in `Padding(padding: EdgeInsets.symmetric(horizontal: 0))` or no padding
- Uses `CardContainer.gold` with `margin: EdgeInsets.zero`
- Background color distinguishes it from list items

## Edge cases

| Scenario | Behavior |
|---|---|
| `authUid == null` | No pinned card, all entries shown normally |
| User not in leaderboard entries | No pinned card, all entries shown normally |
| User at rank 1–5 | Appears normally in list, no pinned card |
| User at rank 6+ | Excluded from list, shown as fixed card at bottom |
| Empty leaderboard | Existing "be first" message shown |
| Only 1 entry (the user, rank 1) | Shown normally in podium/list, no pinned card |
| Tab switch | `displayedCount` resets, scroll resets to top |
| Very long list (100+ entries) | Incremental rendering: 20 at a time, load-more on scroll |
| Streak with 50+ users | Server-side cursor pagination loads pages of 20 |
| Rapid scroll / rapid tab switching | `isLoadingMore` guard prevents duplicate fetches |

## Verification
1. Log in as user ranked > 5 → card fixed at bottom, not in scrollable list
2. Log in as user ranked 1–5 → card in normal list position, no fixed card
3. Log out → no pinned card
4. Scroll long list → more entries load in batches of 20
5. Switch tabs → pagination resets, scroll resets
6. Streak tab with many users → pages load via Firestore cursor
7. Empty leaderboard → "be first" message
8. Rapid scrolling → no duplicate loads, no lag
